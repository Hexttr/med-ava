# Организации и доработка логики приложения

## 1. Резюме идеи

- **Организации** — отдельный раздел: CRUD организаций (название обязательно, фото опционально), внутри каждой — список сотрудников (фото + имя), drag-and-drop загрузка, карточки с полем имени, сохранение.
- **Одиночная обработка** — выбор организации (опционально); при выборе после генерации сотрудник добавляется в организацию и в галерею с привязкой к организации.
- **Пакетная обработка** — два режима: либо выбор организации (показ карточек сотрудников как в разделе «Организации»), либо разовая загрузка фото с карточками и именами.
- **Галерея** — разделы: по организациям и отдельно «Одиночные обработки».

---

## 2. Уточнения и открытые моменты

| Вопрос | Предложение |
|--------|-------------|
| Где хранить организации? | **localStorage** (как настройки/ключ): данные переживают перезагрузку, не нужен бэкенд. При появлении API — слой абстракции (store) заменить на запросы. |
| Что именно «добавляем в организацию» при одиночной генерации? | Запись сотрудника: **имя + исходное фото** (data URL или base64). Сгенерированные медицинский/корпоративный портреты остаются в галерее с полем `organizationId`. |
| Нужно ли в организации хранить сгенерированные портреты? | Не дублировать: организация хранит только **исходные данные** (имя, фото). Связь «сотрудник ↔ портреты» через галерею по `organizationId` + имя (или `employeeId` при желании усложнить модель). |
| Пакетная обработка «по организации»: что генерируем? | Берем сотрудников выбранной организации (фото + имена), запускаем генерацию для каждого; результаты пишем в галерею с `organizationId`. В организации список сотрудников не меняется (уже есть). |
| Импорт/экспорт организаций? | На первом этапе не делать; позже — экспорт/импорт JSON в настройках или отдельной странице. |

## 3. Дополнения и улучшения

1. **Единый компонент карточек сотрудников**  
   Один переиспользуемый блок: превью фото + поле имени + кнопка удаления. Использовать на страницах «Организации», «Пакетная обработка» (оба режима), чтобы интерфейс и поведение совпадали.

2. **Валидация при сохранении организации**  
   Не давать сохранить организацию без имени; при пустом списке сотрудников — предупреждение или разрешить (организация без сотрудников допустима).

3. **Галерея: привязка к организации**  
   Элемент галереи: `organizationId?: string`, `organizationName?: string` (для отображения без лишних запросов). «Одиночные» — элементы без `organizationId`.

4. **Пакетная обработка: явный выбор режима**  
   Переключатель или шаги: «Выбрать организацию» / «Загрузить фото вручную». При выборе организации — подгрузка сотрудников и отображение в тех же карточках, что и на странице организаций (с возможностью временно убрать кого-то из очереди генерации).

5. **Лимиты (опционально)**  
   Ограничение числа организаций или сотрудников в одной организации (например, 50/100), чтобы не переполнять localStorage.

6. **Сортировка в галерее**  
   В разделе по организациям — группировка по организациям, внутри — по дате. «Одиночные» — по дате. Опционально: сортировка по имени организации.

## 4. Архитектура данных

### 4.1. Хранилище (localStorage)

| Ключ | Содержимое |
|------|------------|
| `eam_organizations` | `Organization[]` |
| `eam_gallery` | `GalleryItem[]` (расширить полями `organizationId?`, `organizationName?`) |

### 4.2. Модели

```ts
// Организация
interface Organization {
  id: string
  name: string
  photoUrl: string | null
  employees: OrganizationEmployee[]
  createdAt: number
  updatedAt: number
}

// Сотрудник внутри организации (исходные данные для генерации)
interface OrganizationEmployee {
  id: string
  name: string
  photoUrl: string  // data URL исходного фото
}

// Элемент галереи (как сейчас + привязка к организации)
interface GalleryItem {
  id: string
  name: string
  medicalUrl: string
  corporateUrl: string
  createdAt: number
  organizationId?: string
  organizationName?: string
}
```

### 4.3. Общая логика (store)

- **`lib/organizations-store.ts`** (или хук `useOrganizations`): загрузка/сохранение организаций в localStorage, методы: `getAll`, `getById`, `create`, `update`, `remove`, `addEmployee`, `updateEmployee`, `removeEmployee`.
- **Галерея**: при добавлении элемента (generate/batch) передавать `organizationId` и `organizationName` при выборе организации; при отображении группировать по разделам.

### 4.4. Переиспользуемые компоненты

- **`components/employee-cards.tsx`** (или `organization-employee-cards.tsx`):  
  - Принимает список элементов `{ id, name, photoUrl }` (и при необходимости `File` для пакетной без организации).  
  - Отображает сетку карточек: превью, инпут имени, кнопка удаления.  
  - Поддержка drag-and-drop загрузки новых фото (добавление в список).  
  - Callback’и: `onChange`, `onRemove`, при необходимости `onAddFromFiles`.

Так можно использовать блок и на странице «Организации», и на «Пакетная обработка».

## 5. Экраны и сценарии

### 5.1. Раздел «Организации» (`/organizations`)

- Список организаций: карточки с названием, превью фото организации (если есть), количество сотрудников, кнопки «Редактировать», «Удалить».
- Кнопка «Добавить организацию» → форма/модалка: название (обязательно), фото (опционально) → создание.
- Редактирование организации: та же форма + блок сотрудников:
  - Зона drag-and-drop и выбор файлов для добавления фото.
  - Карточки сотрудников: фото, поле имени, удалить.
  - Кнопка «Сохранить» (организация + список сотрудников).

### 5.2. Одиночная обработка (`/generate`)

- Как сейчас: фото, имя сотрудника.
- **Новое:** выпадающий список «Организация» (опционально), список заполняется из `eam_organizations`.
- Имя и организация необязательны.
- После успешной генерации:
  - Добавить элемент в галерею (как сейчас). Если выбрана организация — передать `organizationId` и `organizationName`.
  - Если выбрана организация — добавить в неё сотрудника: имя (или «Сотрудник»), исходное фото (текущий `file` в виде data URL).

### 5.3. Пакетная обработка (`/batch`)

- **Режим 1 — по организации:** выбор организации из выпадающего списка → подгрузка её сотрудников → отображение в виде тех же карточек (фото + имя). Можно снять галочки или временно убрать кого-то из списка (не удаляя из организации). Кнопка «Сгенерировать» — для отмеченных/всех.
- **Режим 2 — разовая загрузка:** как сейчас: drag-and-drop фото → карточки с именами, без привязки к организации. Генерация → в галерею без `organizationId`.
- При генерации в режиме организации в галерею писать `organizationId` и `organizationName` для каждого результата.

### 5.4. Галерея (`/gallery`)

- Вверху — блок «Одиночные обработки»: карточки без `organizationId`, как сейчас (с удалением, скачиванием, лайтбоксом).
- Ниже — блок «По организациям»: сгруппировать по `organizationId`; для каждой организации — заголовок (название) и карточки портретов этой организации. Внутри группы — те же действия (просмотр, скачать, удалить).
- Кнопки «Скачать все» и «Скачать» на карточке можно оставить в текущей логике (по всем или по одной записи галереи), не обязательно делить архивы по организациям; при желании позже добавить «Скачать по организациям» (архив с папками по именам организаций).

## 6. План поэтапного внедрения

### Этап 1. Модели и хранилище организаций

- Ввести типы `Organization`, `OrganizationEmployee` в `lib/types.ts` (или отдельный файл).
- Реализовать слой работы с localStorage: `lib/organizations-store.ts` — чтение/запись `eam_organizations`, CRUD организаций и сотрудников (добавить/изменить/удалить сотрудника).
- Добавить пункт «Организации» в сайдбар, страницу-заглушку `app/(app)/organizations/page.tsx`.

**Результат:** в навигации есть «Организации», данные можно читать/писать из одного места.

---

### Этап 2. Страница «Организации» (CRUD + сотрудники)

- Список организаций: карточки с названием, фото (если есть), числом сотрудников, кнопками редактировать/удалить.
- Создание организации: форма (название, опциональное фото), кнопка «Создать».
- Редактирование организации: форма + блок сотрудников.
- Компонент карточек сотрудников: drag-and-drop и input file для добавления фото; карточка = превью + инпут имени + удалить; кнопка «Сохранить» сохраняет организацию и список сотрудников в store.

**Результат:** пользователь может создавать/редактировать/удалять организации и управлять списком сотрудников с фото и именами.

---

### Этап 3. Одиночная обработка + привязка к организации

- На странице `/generate`: под полем «Имя сотрудника» выпадающий список организаций (загрузка из store), выбор необязателен.
- При добавлении в галерею передавать `organizationId` и `organizationName`, если организация выбрана.
- Расширить тип `GalleryItem`: поля `organizationId?`, `organizationName?`.
- После успешной генерации при выбранной организации: добавить сотрудника в эту организацию (имя из поля или «Сотрудник», фото — текущий файл в data URL) через `organizations-store`.

**Результат:** одиночная генерация может привязывать результат к организации и добавлять сотрудника в организацию.

---

### Этап 4. Пакетная обработка: два режима

- Переключатель/табы: «По организации» / «Загрузить фото».
- Режим «По организации»: выбор организации из списка → загрузка сотрудников из store → отображение в тех же карточках, что и в «Организациях» (можно вынести общий компонент). Кнопка «Сгенерировать» — для всех (или с возможностью снять галочки с части сотрудников).
- Режим «Загрузить фото»: текущее поведение (drag-and-drop, карточки с именами), без организации.
- При генерации в режиме организации записывать в галерею `organizationId` и `organizationName` для каждого сгенерированного элемента.

**Результат:** пакетная обработка поддерживает и работу с организацией, и разовую загрузку.

---

### Этап 5. Галерея: разделы

- Загрузка галереи из `eam_gallery` с учётом `organizationId` и `organizationName`.
- Раздел «Одиночные обработки»: элементы без `organizationId`, сетка как сейчас.
- Раздел «По организациям»: группировка по `organizationId`; для каждой организации — заголовок с названием и сетка карточек.
- Сохранить текущие действия: удаление, скачать карточку, скачать все, лайтбокс по клику.

**Результат:** галерея разделена на одиночные и по организациям.

---

### Этап 6 (опционально). Доработки

- Единый компонент карточек сотрудников: вынести в `components/employee-cards.tsx` и использовать на «Организации» и «Пакетная».
- Экспорт/импорт организаций (JSON).
- Лимиты на число организаций/сотрудников.
- В галерее: «Скачать все по организациям» (архив с папками по названиям организаций).

---

## 7. Порядок работ (кратко)

1. **Этап 1** — типы, store организаций, пункт меню, заглушка страницы.  
2. **Этап 2** — полная страница «Организации» (список, создание, редактирование, сотрудники с фото и именами).  
3. **Этап 3** — выпадающий список организаций в одиночной обработке, расширение галереи и добавление сотрудника в организацию после генерации.  
4. **Этап 4** — пакетная обработка: режим по организации + режим загрузки фото, запись `organizationId` в галерею.  
5. **Этап 5** — галерея: разделы «Одиночные» и «По организациям».  
6. **Этап 6** — рефакторинг компонентов и опциональные улучшения.

После этапов 1–5 функционал будет соответствовать описанной идее; этап 6 улучшит поддерживаемость и UX.
